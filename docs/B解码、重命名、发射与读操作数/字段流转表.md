# 字段流转表（PD_Instr → D_UOp → R_UOp → IS_UOp → EX_UOp）

本文档单独列出各 UOp 阶段中**字段的有无、类型与流转说明**。结构体定义见 [src/Include.sv](../../src/Include.sv)。

---

## 1. 流水线阶段与结构体对应

| 阶段     | 结构体   | 模块来源           |
|----------|----------|--------------------|
| 预译码后 | PD_Instr | PreDecode          |
| 译码后   | D_UOp    | InstrDecoder       |
| 重命名后 | R_UOp    | Rename             |
| 发射后   | IS_UOp   | IssueQueue 等      |
| 读操作数后 | EX_UOp | Load               |

---

## 2. 字段流转总表

下表每行一个字段（或一组相关字段），列表示该字段在对应结构体中是否存在及简要说明。

| 字段 | 类型/宽度 | PD_Instr | D_UOp | R_UOp | IS_UOp | EX_UOp | 说明/来源 |
|------|-----------|----------|-------|-------|--------|--------|-----------|
| **sqN** | SqN | — | — | ✓ | ✓ | ✓ | 重命名阶段分配；全局顺序号，用于 ROB 索引与误预测废弃；R 起一直透传。 |
| **storeSqN** | SqN | — | — | ✓ | ✓ | ✓ | 重命名阶段按 store 顺序分配；用于 StoreQueue 索引与 store 顺序约束；R 起透传。 |
| **loadSqN** | SqN | — | — | ✓ | ✓ | ✓ | 重命名阶段按 load 顺序分配；用于 LoadBuffer 索引与 load 顺序约束；R 起透传。 |
| **tagDst** | Tag | — | — | ✓ | ✓ | ✓ | 重命名时由 TagBuffer 分配；表示该条指令写回的物理寄存器；R 起透传到执行/写回。 |
| **tagA** | Tag | — | — | ✓ | ✓ | — | RenameTable 查 rs1 得；R/IS 中表示第一源操作数物理寄存器；EX 中已变为 srcA 数值。 |
| **tagB** | Tag | — | — | ✓ | ✓ | — | RenameTable 查 rs2 得；R/IS 中表示第二源操作数物理寄存器；EX 中已变为 srcB 数值。 |
| **tagC** | Tag | — | — | ✓（原子） | — | — | 仅原子指令；为 LD 结果的 tag（与 tagDst 相同），R 中有，入 IQ 后在 StoreDataIQ 等路径处理。 |
| **availA** | logic | — | — | ✓ | ✓ | — | Rename 查表得初值；IQ 内由写回/前递按 tag 更新；出队后 Load 用 tagA 读 RF/前递，不再需要 avail。 |
| **availB** | logic | — | — | ✓ | ✓ | — | 同上，对应 tagB。 |
| **availC** | logic | — | — | ✓（原子） | — | — | 仅原子指令第三操作数就绪位。 |
| **fetchID** | FetchID_t | ✓ | ✓ | ✓ | ✓ | ✓ | 取指阶段分配，标识取指束；全流程透传；Load 用其读 PCFile 取 pc/bpi；ROB 用其做异常/分支恢复。 |
| **fetchOffs** | FetchOff_t | — | ✓ | ✓ | ✓ | ✓ | 指令在取指束内的偏移；D 起透传；EX 中与 PCFile 的 pc 组合得到精确 pc。 |
| **fetchStartOffs** | FetchOff_t | ✓ | — | — | — | ✓ | PD 来自取指；EX 由 Load 从 PCFile 读回（与 fetchID 对应）。 |
| **fetchPredOffs** | FetchOff_t | ✓ | — | — | — | ✓ | PD 为预测分支在束内位置；EX 由 Load 从 PCFile 读回。 |
| **pc** | logic[31:0] | 仅 pc[30:0] | — | — | — | ✓ | PD 为取指 PC；D/R/IS 不存，只保留 fetchID；EX 由 Load 用 fetchID 从 PCFile 读回完整 pc。 |
| **bpi** | BranchPredInfo | — | — | — | — | ✓ | 分支预测信息；仅 EX 有，Load 从 PCFile 按 fetchID 读回。 |
| **instr** | logic[31:0] | ✓ | — | — | — | — | 原始指令字；仅 PD 有，译码后不再保留。 |
| **rs1** | logic[4:0] | — | ✓ | — | — | — | 架构源寄存器 1；仅 D 有，R 中已变为 tagA。 |
| **rs2** | logic[4:0] | — | ✓ | — | — | — | 架构源寄存器 2；仅 D 有，R 中已变为 tagB。 |
| **rd** | RegNm / logic[4:0] | — | ✓ | ✓ | — | — | 架构目标寄存器；D 有，R 保留供提交时更新 RenameTable；IS/EX 不再传，提交用 ROB 等。 |
| **srcA** | logic[31:0] | — | — | — | — | ✓ | 第一源操作数**数值**；仅 EX 有，Load 根据 tagA 从 RF 或前递得到。 |
| **srcB** | logic[31:0] | — | — | — | — | ✓ | 第二源操作数**数值**；仅 EX 有，Load 根据 tagB 从 RF 或前递或 imm 得到。 |
| **imm** | logic[31:0] | — | ✓ | ✓ | ✓ | ✓ | 立即数；译码得到，D 起透传到 EX。 |
| **imm12** | logic[11:0] | — | ✓ | ✓ | ✓ | — | jalr 等用 12 位立即数；D/R/IS 有，EX 中已合并进 imm 或用法不同。 |
| **immB** | logic | — | ✓ | ✓ | ✓ | — | 第二操作数是否为立即数；D 起透传；Load 据此用 imm 填 srcB。 |
| **opcode** | logic[5:0] | — | ✓ | ✓ | ✓ | ✓ | 内部操作码；D 起透传。 |
| **fu** | FuncUnit | — | ✓ | ✓ | ✓ | ✓ | 功能单元；D 起透传，决定进哪类 IQ、走哪条执行路径。 |
| **compressed** | logic | ✓(is16bit) | ✓ | ✓ | ✓ | ✓ | 是否压缩指令；PD 为 is16bit，D 起为 compressed，透传。 |
| **valid** | logic | ✓ | ✓ | ✓ | ✓ | ✓ | 有效位；各阶段均有；R 另有 validIQ 表示可进哪些 IQ。 |
| **validIQ** | logic[] | — | — | ✓ | — | — | 仅 R 有；每位表示该 UOp 是否可进入对应 IssueQueue 端口。 |
| **predTarget** | logic[30:0] | ✓ | — | — | — | — | 预测目标 PC；仅 PD，供前端修正。 |
| **predTaken** | logic | ✓ | — | — | — | — | 预测是否 taken；仅 PD。 |
| **fetchFault** | IFetchFault | ✓ | — | — | — | — | 取指故障；仅 PD。 |

## 3. 字段生命周期表

下表按**产生 → 使用/传递 → 消亡**描述各字段在流水线中的生命周期。  
- **产生阶段**：该字段首次出现于哪一 UOp 阶段、由谁生成。  
- **使用/传递阶段**：在哪些阶段被使用（透传、读表、写回、消费等）。  
- **消亡阶段**：在哪个阶段之后该字段不再存在于 UOp 结构体中（或已转化为其他字段）。

| 字段 | 产生阶段 | 使用/传递阶段 | 消亡阶段 | 备注 |
|------|----------|----------------|----------|------|
| **sqN** | R（Rename 分配） | R→IS→EX 透传；ROB 入队/提交、误预测比较 | 提交后 ROB 仍持有一段时间，UOp 链上到 EX 为止 | 全局顺序号，比 ROB 索引多 1 位便于有符号比较 |
| **storeSqN** | R（Rename 按 store 递增） | R→IS→EX 透传；StoreQueue/StoreDataIQ 入队与容量检查 | 同 sqN | store 顺序与 SQ 索引 |
| **loadSqN** | R（Rename 按 load 递增） | R→IS→EX 透传；LoadBuffer、load 顺序约束 | 同 sqN | load 顺序与 LB 索引 |
| **tagDst** | R（TagBuffer 分配） | R→IS→EX 透传；写回写 RF、前递匹配、提交时释放 tag | 提交后 TagBuffer 释放；物理寄存器生命周期更长 | 仅写寄存器指令分配；TAG_ZERO 等特殊值不占物理寄存器 |
| **tagA** | R（RenameTable 查 rs1） | R/IS 内用于就绪判断与透传；Load 用其读 RF/前递 | EX：在 Load 中消费后不再携带，变为 srcA | 源 1 的物理寄存器标识 |
| **tagB** | R（RenameTable 查 rs2） | R/IS 内用于就绪判断与透传；Load 用其读 RF/前递 | EX：在 Load 中消费后不再携带，变为 srcB | 源 2 的物理寄存器标识 |
| **tagC** | R（原子指令设为 tagDst） | R 内及 StoreDataIQ 路径用于原子第三操作数就绪 | 入 StoreDataIQ 等后在该路径内消费，IS/EX 主链不传 | 仅原子指令 |
| **availA** | R（RenameTable 查表得初值） | R/IS 内由写回/前递更新，用于可发射判断 | IS 出队后：Load 只看 tagA，不再需要 availA | 仅“是否就绪”状态，不传数值 |
| **availB** | R（同上） | R/IS 内更新与可发射判断 | IS 出队后消亡 | 同上 |
| **availC** | R（原子初值为 0） | R 及 StoreDataIQ 内更新 | 入 Store 数据路径后在该路径内消亡 | 仅原子 |
| **fetchID** | PD（IFetch/PreDecode 分配） | PD→D→R→IS→EX 全链透传；Load 用其读 PCFile；ROB 用其恢复 PC | 提交后 PCFile/BPFile 条目可释放，fetchID 语义结束 | 取指束级标识，省去在各 UOp 存完整 PC |
| **fetchOffs** | D（译码得到） | D→R→IS→EX 透传；EX 与 PCFile 的 pc 组合成精确 pc | 执行/提交后不再需要 | 束内指令偏移 |
| **fetchStartOffs** | PD | PD 存；EX 由 Load 按 fetchID 从 PCFile 读回 | PD 后 D/R/IS 不存；EX 使用后随 UOp 结束 | 束起始偏移 |
| **fetchPredOffs** | PD | PD 存；EX 从 PCFile 读回 | 同上 | 预测分支在束内位置 |
| **pc** | PD（仅存 pc[30:0]） | PD 使用；D/R/IS 不存；EX 由 Load 从 PCFile 读回完整 pc | 每阶段：PD 后即不传；EX 使用后随 UOp 结束 | 为省面积 D/R/IS 只保留 fetchID |
| **bpi** | 取指时写入 PCFile | EX 由 Load 按 fetchID 从 PCFile 读回 | EX 使用后随 UOp 结束 | 仅 EX 阶段存在于 UOp |
| **instr** | PD（PreDecode 输出） | PD→D 供 InstrDecoder 译码 | D：译码后不再保留 | 仅 PD 有，译码即消费 |
| **rs1** | D（InstrDecoder 从 instr 解析） | D→R 供 RenameTable 查表 | R：查表得到 tagA 后不再传递 | 架构寄存器号，重命名后由 tagA 替代 |
| **rs2** | D（同上） | D→R 供 RenameTable 查表 | R：查表得到 tagB 后不再传递 | 同上 |
| **rd** | D（译码得到） | D→R 透传；提交时 ROB 用 rd 更新 RenameTable | IS：入 IQ 后不再随 UOp 传递；提交在 ROB 侧完成 | 提交时需架构号以更新映射 |
| **srcA** | EX（Load 根据 tagA 读 RF/前递） | EX 供各 FU 使用 | 执行完成后随结果写回等，不进入下一 UOp 阶段 | 仅 EX 存在，替代 tagA 的“值”角色 |
| **srcB** | EX（Load 根据 tagB/immB 得到） | EX 供各 FU 使用 | 同上 | 同上 |
| **imm** | D（译码得到） | D→R→IS→EX 透传；EX 中可能填 srcB 或参与运算 | 执行后消亡 | 全程透传的立即数 |
| **imm12** | D（译码得到） | D→R→IS 透传；jalr 等在 Load/执行中用 | EX 中不再单独存在（合并进 imm 或已用） | 部分指令 12 位立即数 |
| **immB** | D（译码得到） | D→R→IS 透传；Load 据此选 srcB 来自 imm 或 RF | EX 中不再需要（已得到 srcB） | 控制第二操作数来源 |
| **opcode** | D（译码得到） | D→R→IS→EX 透传；各阶段选 FU、控制运算 | 执行后消亡 | 内部操作码 |
| **fu** | D（译码得到） | D→R→IS→EX 透传；决定进哪类 IQ、走哪条执行路径 | 执行后消亡 | 功能单元选择 |
| **compressed** | PD（is16bit） | PD 存；D 起以 compressed 透传到 EX | 执行后消亡 | PD 与 D 字段名不同 |
| **valid** | PD | 每阶段均有，表示该拍该槽 UOp 有效 | 无效或废弃后该槽无有效 UOp | 每阶段独立使用 |
| **validIQ** | R（Rename 根据 Scheduler 等填） | R 入队时各 IQ 根据对应位决定是否接收 | IS：出队后不再需要 | 仅 R 存在，入队即消费 |
| **predTarget** | PD | PD 供 BranchHandler 等前端使用 | D：不传入译码 | 仅 PD 生命周期 |
| **predTaken** | PD | PD 供前端使用 | D：不传入译码 | 仅 PD 生命周期 |
| **fetchFault** | PD | PD 供异常/故障处理 | D：不传入译码 | 仅 PD 生命周期 |

**生命周期小结（按“存活长度”）**  
- **全链存活**：fetchID、imm、opcode、fu、compressed、valid、sqN、storeSqN、loadSqN、tagDst（R→EX）。  
- **PD 仅存**：instr、predTarget、predTaken、fetchFault、pc/fetchStartOffs/fetchPredOffs（EX 再从 PCFile 读回）。  
- **D 仅存**：rs1、rs2。  
- **D→R 存**：rd。  
- **R 仅存**：validIQ；tagC、availC（原子路径）。  
- **R→IS 存**：tagA、tagB、availA、availB；imm12、immB 到 IS 止。  
- **EX 才存**：srcA、srcB、pc、bpi、fetchStartOffs、fetchPredOffs（从 PCFile 读回）。

## 4. 重点字段流转示意

```
sqN / storeSqN / loadSqN:
  [无] → [无] → [Rename 分配] → [透传] → [透传]
  用于：ROB 顺序、误预测废弃、StoreQueue/LoadBuffer 索引与容量约束

tagDst:
  [无] → [无] → [TagBuffer 分配] → [透传] → [透传至写回]
  用于：物理寄存器写回、前递匹配、提交时释放旧 tag

tagA / tagB:
  [无] → [无] → [RenameTable 查 rs1/rs2] → [透传] → [在 Load 中消费，变为 srcA/srcB]
  用于：IQ 内就绪判断、Load 级 RF 读与前递选择

fetchID:
  [取指分配] → [透传] → [透传] → [透传] → [透传；Load/ROB 用其读 PCFile]
  用于：PC/分支预测恢复、异常提交时取 PC
```
