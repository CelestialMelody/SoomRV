# SoomRV 体系结构阅读顺序指南

从**计算机体系结构**角度理解 SoomRV 时，建议按下面的顺序阅读，把「概念 → 数据流 → 代码」对应起来。每个阶段都标明了**相关概念**、**推荐文档**和**阅读顺序**。

---

## 一、阅读前准备：全局视角与数据结构

### 1.1 建立整体图景

- **先读**：`docs/README.zh.md`、`docs/Overview.zh.md`、`docs/architect.zh.md`  
- **目的**：弄清这是一颗**超标量乱序、标签重命名、发射后读操作数**的 RV32 核；指令流大致是 **取指 → 预解码/对齐 → 解码 → 重命名 → 发射队列 → Load 读操作数 → 执行 → ROB 提交**，以及 Store/Load 的缓冲与顺序。

### 1.2 数据结构与配置（所有阶段的“语言”）

- **必读**：`src/Include.sv`（选读：`src/Config.sv`）  
- **目的**：  
  - **UOp 族**：`D_UOp` → `R_UOp` → `IS_UOp` → `EX_UOp` → `AGU_UOp` / `LD_UOp` / `SQ_UOp` 等，理解每条指令在流水线各阶段用哪些字段（pc、fetchID、sqN、tagDst、loadSqN/storeSqN 等）。  
  - **分支/预测**：`PredBranch`、`BranchProv`、`FetchBranchProv`、`BTUpdate`、`BPUpdate`。  
  - **取指/预解码**：`IFetchOp`、`IF_Instr`、`PD_Instr`。  
- **建议**：不必一次全懂，可在后面每个阶段回头查用到的结构体。

### 1.3 顶层：Core 与 SoC

- **读**：`src/Core.sv` 前 150 行（模块列表与主要连线）、`src/SoC.sv` 前 100 行  
- **目的**：看到 **IFetch → PreDecode/Decode → Rename → Scheduler/IssueQueue → Load → 各 FU（IntALU、AGU、FPU 等）→ ROB** 以及 **Cache/MemoryController**、**MMIO** 在顶层如何挂接；分支预测的 **IN_branch**、**IN_btUpdates**、**IN_bpUpdate** 从哪来、到哪去。

---

## 二、分支预测（决定“取哪条指令”）

**体系结构要点**：控制冒险、预测下一 PC、目标预测 vs 方向预测、恢复。

- **推荐文档**：`docs/分支预测实现详解.md`  
- **阅读顺序**：  
  1. `docs/分支预测实现详解.md` 的「整体结构」和「BranchPredictor 顶层」——理解 **OUT_pc / OUT_predBr** 如何驱动取指，**IN_mispr / IN_bpUpdate / IN_btUpdates** 如何更新与恢复。  
  2. `src/BranchTargetBuffer.sv`（目标预测：BTB 读/写、索引与 tag）。  
  3. `src/TagePredictor.sv` + `src/BranchPredictionTable.sv`（方向预测：bimodal + TAGE）。  
  4. `src/ReturnStack.sv`（返回地址预测）。  
  5. `src/BranchHandler.sv`（取指阶段用实际指令修正预测、产生 BTUpdate）。  
  6. `src/BranchSelector.sv`（后端多条分支结果选“最早”的 mispred）。  
- **与流水线的关系**：分支预测输出「下一拍取指 PC」；错误预测时 **IN_branch.taken** 触发前端恢复（见下文“流水线冲突与恢复”）。

---

## 三、取指与 I-Cache、ITLB（指令供给）

**体系结构要点**：取指带宽、指令缓存、VIPT、地址翻译、取指冒险（stall、flush）。

- **推荐文档**：`docs/取指实现详解.md`  
- **阅读顺序**：  
  1. `docs/取指实现详解.md` 的「数据流」和「IFetch / IFetchPipeline」——从 **OUT_pc** 到 **IFetchOp → fetch0/fetch1 → I-Cache/ICTable 读 → TLB 翻译 → 组 IF_Instr → BranchHandler 修正 → FIFO → InstrAligner → PD_Instr**。  
  2. `src/IFetch.sv`（使能、ifetchOp 生成、与 BranchPredictor 的接口）。  
  3. `src/IFetchPipeline.sv`（两级 fetch、ICache/ICTable 访问、TLB_req/TLB_res、phyPC、cache hit/miss、packet/packetRePred、FIFO、stall 条件）。  
  4. **I-Cache 与存储层次**：在 `src/SoC.sv` 中搜 **IF_icache**、**IF_ict**，看如何接到 **MemRTL1RW**、**CacheLineManager** 以及 **MemoryController** 的请求；理解 VIPT 索引（`pc[VIRT_IDX_LEN-1:0]`）+ 物理 tag 比较。  
  5. **ITLB**：`src/IFetchPipeline.sv` 中的 **TLB_req**、**itlb** 实例、**TLB_res**、**phyPC**、**pageFault**、**tlbMiss**；再读 `src/TLB.sv`（或 `TLB_fixed.sv`）的接口与查表逻辑。  
- **冲突与冒险**：取指 stall（FIFO 满、fetchLimit、cache busy、flush）；cache miss / TLB miss 时发 **OUT_fetchBranch** 重新取指；**IN_mispr** 时整条取指流水线被 flush。

---

## 四、预解码与指令对齐、解码（从“字节流”到“微操作”）

**体系结构要点**：变长指令（16/32 位）、指令边界、解码宽度、异常/故障传递。

- **阅读顺序**：  
  1. `src/InstrAligner.sv`：如何把 **IF_Instr**（8 个半字）按 **firstValid/lastValid** 和 **instrs[i][1:0]==2'b11** 切成多条 **PD_Instr**，输出给解码器。  
  2. `src/InstrDecoder.sv`：**PD_Instr** → **D_UOp**（opcode、rd/rs1/rs2、imm、fu、fetchID、fetchOffs 等）；**fetchFault** 如何映射到 TRAP_*。  
- **与流水线的关系**：解码宽度 `DEC_WIDTH`（4），为后续重命名与发射宽度一致；故障在 D_UOp 中携带，直到提交时由 TrapHandler/CSR 处理。

---

## 五、重命名与 ROB（消除 WAR/WAW、为乱序提供标签与顺序）

**体系结构要点**：寄存器重命名、物理寄存器/标签、ROB、序列号（sqN）、推测与提交顺序。

- **推荐**：`docs/Overview.zh.md` 中「Rename」「ROB」两节。  
- **阅读顺序**：  
  1. `src/Rename.sv`：**D_UOp** → **R_UOp**；分配 **sqN**、**tagDst**；用 **RenameTable** 把 rs1/rs2 映射为 **tagSrcA/tagSrcB**；指令消除（NOP、小立即数等）。  
  2. `src/RenameTable.sv`：虚拟寄存器 → 物理 tag 的映射；**commit** 时释放 tag；**mispred** 时恢复为已提交状态。  
  3. `src/ROB.sv`：入口在重命名后创建；指令完成时标记完成；**按序提交**、**OUT_comUOp**、**OUT_bpUpdate**、**OUT_curFetchID**；**mispred** 时 flush 与重放恢复 RenameTable。  
- **冲突与恢复**：错误预测时 **branch.taken** 使 ROB 中后续条目无效，并从 ROB 重放以恢复 RenameTable，见 Overview 与 ROB 中 branch 相关逻辑。

---

## 六、动态调度：发射队列与调度器（指令级并行的核心）

**体系结构要点**：乱序发射、操作数就绪、功能单元分配、WAK 冒险通过 tag 匹配解决。

- **推荐**：`docs/Overview.zh.md` 中「IssueQueue」「Load」两节。  
- **阅读顺序**：  
  1. `src/Scheduler.sv`：各 IssueQueue 的仲裁与背压（stall）。  
  2. `src/IssueQueue.sv`：**R_UOp** 入队；用 **tag** 跟踪操作数就绪；就绪且 FU 空闲时 **IS_UOp** 出队；可能多端口、多队列。  
  3. `src/Load.sv`：**IS_UOp** 进入后读 **RegFile** 与 **forward** 得到 **srcA/srcB**，得到 **EX_UOp**；读 **PCFile** 得到 pc/bpi 等；理解「发射后才读操作数」如何避免在 IQ 里存大量数据。  
- **相关**：`src/RegFileRTL.sv`（多读多写）、`src/TagBuffer.sv`（完成时写回 tag→数据）；forward 网络在 Load 或周围逻辑中由 **tagDst** 与完成总线匹配。

---

## 七、执行阶段与功能单元（ALU、分支、访存地址、浮点）

**体系结构要点**：多 FU、分支解析、间接跳转、store 数据与地址分离。

- **阅读顺序**：  
  1. `src/IntALU.sv`：**EX_UOp** 执行整数运算与分支；**branchTaken**、**BranchProv**（mispred 时 taken、dstPC、histAct）；**BTUpdate**（间接跳转目标写回 BTB）。  
  2. `src/AGU.sv`：地址计算、**TLB 翻译**（数据侧）、**AGU_UOp** 送给 LoadBuffer/StoreQueue。  
  3. 其他 FU：`Multiply.sv`、`Divide.sv`、`FPU.sv` 等按需浏览，重点看 **IN_branch** 与 **OUT_uop**（完成写回 tag）。  
- **冲突**：**IN_branch.taken** 时所有 FU 对「晚于该分支」的 uop 无效（通过 sqN 比较）。

---

## 八、流水线冲突与错误预测恢复（统一视角）

**体系结构要点**：控制冒险、结构冒险、数据冒险、squash、恢复 Rename 与 BP 状态。

- **阅读顺序**：  
  1. **控制冒险**：`src/BranchSelector.sv` 选出 **OUT_branch**（最早 mispred）；在 **Core.sv** 中该信号连到 **IFetch** 的 **IN_branch** 和 **Rename/ROB** 等的 **IN_branch**；IFetch 将 **IN_branch** 转为 **BP_mispr**，BranchPredictor 恢复 **pcReg/history/ReturnStack**；ROB 与 RenameTable 做 flush 与重放。  
  2. **结构冒险**：IssueQueue 满、ROB 满、LoadBuffer/StoreQueue 满时，前端或调度器 stall（见 Scheduler、Core 中 stall 汇总）。  
  3. **数据冒险**：通过 **tag** 在 IssueQueue 中等待「生产者写回」；Load 阶段读 RegFile 与 forward；LoadBuffer 检测 load 与前面 store 的依赖（store 未提交时 load 可能被重放）。  
- **关键文件**：`src/TrapHandler.sv`（**OUT_disableIFetch**、stall 汇总）、`src/ROB.sv`（flush、重放）、`src/Rename.sv` 与 **RenameTable** 的恢复。

---

## 九、内存子系统：D-Cache、TLB、MMU、Store/Load 顺序

**体系结构要点**：Load/Store 乱序与顺序约束、Store Queue、Load Buffer、VIPT、页表遍历。

- **阅读顺序**：  
  1. **AGU 之后**：`src/LoadBuffer.sv`（未提交 load 缓冲、与 store 顺序）、`src/StoreQueue.sv`（未提交 store、forward 给 load）、`src/StoreQueueBackend.sv`（提交后 store 融合写回）。  
  2. **LSU 与 D-Cache**：`src/LoadStoreUnit.sv`（**IF_cache** 读/写、hit/miss、MMIO 旁路）；`src/BypassLSU.sv`（外部 MMIO）；`src/CacheReadInterface.sv`、`src/CacheWriteInterface.sv`；在 SoC 中看 D-Cache 与 **CacheLineManager**、**MemoryController** 的连接。  
  3. **TLB 与 MMU**：`src/TLB.sv`（查 VPN→PPN、权限）；`src/PageWalker.sv`（缺页时走页表）；`src/TLBMissQueue.sv`（多请求排队）；AGU 中发 **TLB_req**、收 **TLB_res**，以及 **OUT_pw**/IN_pw 与 PageWalker 的接口。  
- **冲突**：load 依赖未提交 store 时在 LoadBuffer 中等待或重放；store 与 load 的地址冲突检测；TLB miss 时 stall 直到 PageWalker 完成。

---

## 十、提交、异常与 CSR（顺序出口与状态）

**体系结构要点**：按序提交、异常精确、CSR 读写、中断。

- **阅读顺序**：  
  1. `src/ROB.sv`：提交条件、**OUT_comUOp**、**OUT_bpUpdate**、**OUT_trapUOp**、**OUT_curFetchID**；trap 时 **OUT_trapUOp** 与 **flush**。  
  2. `src/CSR.sv`：CSR 读/写、**mstatus/mepc/mcause/mtvec** 等、与 **TrapHandler** 的配合。  
  3. `src/TrapHandler.sv`：根据 trap 与 **OUT_disableIFetch** 等产生全局 stall/flush；与 MMIO（如 mtime）的交互可在 **MMIO.sv**、**Peripherals.sv** 中看。

## 十二、按“主题”横向串起来读

- **指令级并行**：R_UOp 多路进入多个 IssueQueue → 就绪即发射 → Load 读操作数 → 多 FU 并行执行 → ROB 按序提交；重点看 **Scheduler**、**IssueQueue**、**Load**、**Core** 中多端口与 tag 流。  
- **流水线冲突**：结构（队列满、cache busy）→ Scheduler/IFetchPipeline 的 stall；数据（RAW）→ tag 与 forward；控制（mispred）→ BranchSelector → IN_branch → BP 恢复 + ROB/Rename flush。  
- **MMU/TLB**：取指用 ITLB（IFetchPipeline）；访存用 DTLB（AGU）；TLB.sv、PageWalker.sv、TLBMissQueue.sv；VirtMemState、rootPPN 等在 CSR/MMU 相关逻辑中。  
- **Cache 层次**：I-Cache（IFetchPipeline + SoC）；D-Cache（LoadStoreUnit + CacheReadInterface/CacheWriteInterface + SoC）；CacheLineManager、MemoryController 在 SoC 中统一接内存与总线。

按上述「阶段顺序」或「主题横向」读一遍后，再针对某一块（如只做 TAGE 或只做 StoreQueue）精读对应文件即可把体系结构概念和实现一一对应起来。
