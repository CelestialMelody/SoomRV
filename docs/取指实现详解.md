# SoomRV 取指（Instruction Fetch）实现详解

本文档结合代码逐级说明取指从「下一个 PC」到「输出给解码器的 PD_Instr」的完整路径。取指涉及模块：**IFetch**、**BranchPredictor**、**IFetchPipeline**、**BranchHandler**、**InstrAligner**，以及 I-Cache/ICTable、ITLB、内存请求等。

---

## 一、整体数据流与关键类型

### 1.1 数据流概览

```
                    ┌─────────────────┐
                    │ BranchPredictor │
                    │  (下一拍 PC)     │
                    └────────┬────────┘
                             │ pc (30:0), predBr
                             ▼
┌──────────────────────────────────────────────────────────────────────────┐
│ IFetch                                                                   │
│   ifetchOp.valid=1, ifetchOp.pc = {pc,1'b0}  (仅当 !stall && !mispred)   │
└────────────────────────────┬─────────────────────────────────────────────┘
                             │ IFetchOp
                             ▼
┌──────────────────────────────────────────────────────────────────────────┐
│ IFetchPipeline                                                            │
│   fetch0 ← ifetchOp (第 0 拍)                                             │
│   fetch1 ← fetch0, 分配 fetchID (第 1 拍)                                  │
│   → 读 I-Cache/ICTable → TLB 翻译 → 判 cache hit/miss → 组装 IF_Instr      │
│   → BranchHandler 修正预测 → packetRePred → outFIFO → InstrAligner        │
└────────────────────────────┬─────────────────────────────────────────────┘
                             │ IF_Instr (后经 FIFO) → InstrAligner
                             ▼
┌──────────────────────────────────────────────────────────────────────────┐
│ InstrAligner                                                              │
│   IF_Instr (8 个半字) → 按 16/32 位边界切分 → 输出 DEC_WIDTH 条 PD_Instr   │
└────────────────────────────┬─────────────────────────────────────────────┘
                             │ PD_Instr[`DEC_WIDTH-1:0]
                             ▼
                         Decode (InstrDecoder)
```

### 1.2 关键类型定义（Include.sv）

**取指请求（发往流水线）：**


- **pc**：本拍要取的 32 位地址（字节对齐时低 1 位为 0）。
- **fetchID**：在 IFetchPipeline 中分配，用于 PC/BP 文件和错误预测恢复。
- **fetchFault**：取指前就已知的故障（如中断待处理）。
- **lastValid**：本 fetch bundle 中「最后一个有效半字」在 16 字节内的偏移（由分支预测给出）。
- **predBr**：本 bundle 的预测分支信息（目标、是否 taken、偏移等）。

**取指结果（一包 16 字节原始指令）：**


## 二、IFetch 模块（src/IFetch.sv）

IFetch 的职责：在**无 stall、无错误预测**时，根据**分支预测器给出的 PC** 生成**本拍有效的 IFetchOp**，并接入 BranchPredictor 与 IFetchPipeline。

### 2.1 使能条件

```117:124:src/IFetch.sv
wire baseEn = IN_en && !waitForInterrupt && !issuedInterrupt && !BP_stall;

// When first encountering a fault, we output a single fake fault instruction.
// Thus ifetch is still enabled during this first fault cycle.
wire ifetchEn /* verilator public */ =
    baseEn && !icacheStall;
```

- **IN_en**：来自 Core，且会与 `!TH_disableIFetch` 相与（TrapHandler 可关断取指）。
- **waitForInterrupt**：上电或 WFI 后的一段时间内为 1，防止取指。
- **BP_stall**：分支预测器 stall（如 ReturnStack 等）时不再递送新 PC。
- **icacheStall**：IFetchPipeline 内部 stall（FIFO 满、fetchLimit、cache busy、flush 等）。

### 2.2 生成 IFetchOp（组合逻辑）

```204:214:src/IFetch.sv
IFetchOp ifetchOp;
always_comb begin
    ifetchOp = IFetchOp'{valid: 0, default: 'x};

    if (IN_branch.taken || BH_fetchBranch.taken) begin
    end
    else if (ifetchEn) begin
        ifetchOp.valid = 1;
        ifetchOp.pc = {pc, 1'b0};
        ifetchOp.fetchFault = IN_interruptPending ? IF_INTERRUPT : IF_FAULT_NONE;
    end
end
```

- **IN_branch.taken** 或 **BH_fetchBranch.taken**：本拍是错误预测或 fetch 内部分支修正，**不**发出新 ifetchOp（valid 保持 0）。
- **else if (ifetchEn)**：正常取指时，**pc** 来自 BranchPredictor 的 `OUT_pc`（30 位，表示「半字地址」），这里拼成 32 位字节地址 `{pc, 1'b0}`；若存在待处理中断则打上 **IF_INTERRUPT**。

其余字段（fetchID、lastValid、predBr 等）在 **IFetchPipeline** 中按拍填充。

### 2.3 错误预测 / 修正来源（BP_mispr）

```56:83:src/IFetch.sv
FetchBranchProv BP_mispr;
always_comb begin
    BP_mispr = BH_fetchBranch;
    if (IN_branch.taken) begin
        BP_mispr = FetchBranchProv'{
            taken: IN_branch.taken,
            fetchID: IN_branch.fetchID,
            dst: IN_branch.dstPC[31:1],
            ...
        };
    end

        BP_mispr = FetchBranchProv'{ ... };
    end

```

- **IN_branch**：来自后端（BranchSelector），提交阶段确认的错误预测。
- **IN_decBranch**：解码阶段发现的立即跳转（如 jal）等，需清空前端。
- **BH_fetchBranch**：IFetchPipeline 里 BranchHandler 发现的「预测错误」或 cache miss/tlb miss 导致的重新取指。

三者统一成 **BP_mispr** 送给 BranchPredictor，用于恢复 PC 与预测状态。

### 2.4 子模块连接

- **BranchPredictor**：输出下一拍 **pc**、**predBr**、**OUT_fetchLimit** 等；接收 **BP_mispr**、**IN_btUpdates**、**IN_bpUpdate**，并读写 **PCFile / BPFile**。
- **IFetchPipeline**：输入 **ifetchOp**，输出 **OUT_instrs**（PD_Instr 数组）；内部产生 **icacheStall**、**BH_fetchBranch**、**BH_btUpdate**、**BH_retDecUpd** 等。

## 三、BranchPredictor（下一拍 PC 来源）

BranchPredictor 在**每个取指使能拍**给出「下一拍要取的 PC」以及本包的预测分支信息。

### 3.1 PC 的更新（寄存器 pcReg）

```326:365:src/BranchPredictor.sv
reg[30:0] pcReg;
reg[30:0] pcRegNoInc;
...
always_ff@(posedge clk ...) begin
    ...
    if (IN_pcValid) begin
        pcReg <= {OUT_pc[30:$bits(FetchOff_t)] + 1'b1, $bits(FetchOff_t)'(1'b0)};
        pcRegNoInc <= OUT_pc;
        ...
    end
    ...
    if (IN_mispr.taken) begin
        ...
        pcReg <= IN_mispr.tgtSpec == BR_TGT_MANUAL ? IN_mispr.dst : 'x;
        ignorePred <= 1;
    end
end
```

- **IN_pcValid**：即 IFetch 的 ifetchEn；为 1 时，下一拍 **pcReg** 为「本拍输出的 OUT_pc 按 16 字节对齐向下一个 16 字节推进」。
- **IN_mispr.taken**：错误预测时，**pcReg** 被设为恢复目标（若 tgtSpec==BR_TGT_MANUAL 则直接用 **IN_mispr.dst**）。

### 3.2 本拍输出的 PC 与预测分支（OUT_pc, OUT_predBr）

```96:139:src/BranchPredictor.sv
always_comb begin
    OUT_predBr = '0;
    OUT_predBr.dst = OUT_curRetAddr;
    OUT_predBr.offs = {$bits(FetchOff_t){1'b1}};

    OUT_pc = pcReg;

    if (ignorePred) begin
        if (recovery.valid && recovery.tgtSpec != BR_TGT_MANUAL)
            OUT_pc = recoveredPC;
    end
    else if (BTB_br.valid && BTB_br.btype != BT_RETURN) begin
        OUT_predBr = BTB_br;
        OUT_predBr.taken |= TAGE_taken;
        ...
        if (OUT_predBr.taken) begin
            OUT_pc = OUT_predBr.dst;
            OUT_lastOffs = OUT_predBr.offs;
        end
        ...
    end
    else if (BTB_br.valid && BTB_br.btype == BT_RETURN && RET_br.valid) begin
        OUT_predBr = BTB_br;
        OUT_predBr.taken = 1;
        OUT_predBr.dst = OUT_curRetAddr;
        OUT_pc = OUT_predBr.dst;
        ...
    end
    else begin
        OUT_predBr.valid = 1;
        OUT_predBr.btype = BT_BRANCH;
        OUT_predBr.dirOnly = 1;
        OUT_predBr.taken = TAGE_taken;
    end
end
```

- **BTB_br**：BranchTargetBuffer 根据当前 **OUT_pc** 查到的跳转/调用/返回目标与类型。
- **TAGE_taken**：TagePredictor 对条件分支方向的预测。
- **OUT_curRetAddr**：ReturnStack 给出的预测返回地址。
- 若 BTB 命中且非 return：取目标则 **OUT_pc = OUT_predBr.dst**，并给出 **OUT_predBr.offs** 等。
- 若为 return 且 ReturnStack 有效：**OUT_pc = OUT_curRetAddr**。
- 否则仅方向预测：**OUT_predBr.dirOnly=1**，**OUT_pc** 仍为顺序下一包（由上面 pcReg 的更新体现）。

因此，**IFetch 中 ifetchOp.pc = {pc, 1'b0}** 里的 **pc** 就是本组合逻辑输出的 **OUT_pc**（上一拍已存于 pcReg，本拍用于取指）。

## 四、IFetchPipeline（src/IFetchPipeline.sv）

IFetchPipeline 完成：**接收 IFetchOp → 访问 I-Cache/ICTable → 地址翻译 → 判 hit/miss → 组 IF_Instr → BranchHandler 修正 → 输出 FIFO → InstrAligner**。

### 4.1 流水线两级：fetch0、fetch1

```455:476:src/IFetchPipeline.sv
IFetchOp fetch0 /* verilator public */;
IFetchOp fetch1 /* verilator public */;
always_ff@(posedge clk ...) begin
    fetch0 <= IFetchOp'{valid: 0, default: 'x};
    fetch1 <= IFetchOp'{valid: 0, default: 'x};
    ...
    else begin
        ...
        if (IN_ifetchOp.valid && !OUT_stall) begin
            fetch0 <= IN_ifetchOp;
        end
        if (fetch0.valid) begin
            fetch1 <= fetch0;
            fetch1.fetchID <= fetchID;
            fetch1.lastValid <= IN_lastValid;
            fetch1.predBr <= IN_predBranch;
            fetch1.predRetAddr <= IN_lateRetAddr;
            fetch1.rIdx <= IN_rIdx;

            fetchID <= fetchID + 1;
        end
        ...
    end
end
```

- **第 0 拍**：若 `IN_ifetchOp.valid && !OUT_stall`，则 **fetch0** 保存本拍 ifetchOp（含 pc）。
- **第 1 拍**：**fetch1** 保存上一拍的 fetch0，并**在本拍为这一包分配 fetchID**，同时把 BranchPredictor 提供的 **IN_lastValid**、**IN_predBranch**、**IN_lateRetAddr**、**IN_rIdx** 打入 fetch1。

因此，**对 I-Cache 的读地址应使用「与 fetch1 对应的 PC」**；但**发起读请求**是在「fetch0 有效」的那一拍用 **IN_ifetchOp.pc**（即上一拍的 PC）完成的，见下。

### 4.5 组 packet：故障、cache hit、cache miss


- 若有**故障**：只填 pc、firstValid/lastValid、fetchFault、valid=1，instrs 置 0。
- 若 **cache hit**：填 **packet.instrs = assocHitInstrs**，以及 pc、firstValid、lastValid、predPos/predTaken/predTarget、fetchID，**packet.valid = 1**。

- 页表遍历忙、FIFO 空间不足、达到 **fetchLimit**、正在 flush I-Cache、或 I-Cache 返回 busy 时，**OUT_stall=1**，IFetch 本拍不会递送新的 ifetchOp。

## 五、BranchHandler（src/BranchHandler.sv）简要

BranchHandler 输入为**当前 fetch bundle 的 IFetchOp（fetch1）和 8 个半字 IN_instrs**，通过 RISC-V 编码识别 16/32 位指令边界和所有分支/跳转指令，并输出：

- **OUT_decBranch**：若本包内存在「预测错误」的跳转（目标或是否 taken 与预测不符），则 taken=1 并给出正确目标与位置。
- **OUT_btUpdate** / **OUT_retUpdate**：用于更新 BTB 和 ReturnStack。
- **OUT_endOffsValid** / **OUT_endOffs**：实际分支所在半字偏移，用于把 **packet.lastValid** 截断到该分支之前（见上节 packetRePred）。

例如对 16 位指令的识别（节选）：

```42:71:src/BranchHandler.sv
for (integer i = 1; i < NUM_INST+1; i=i+1) begin
    ...
    if (validInstrStart) begin
        if (instrsView[i][1:0] == 2'b11) begin
            is32bit[i] = 1;
            validInstrStart = 0;
        end
        else begin
            is16bit[i] = 1;
            validInstrStart = 1;
        end
    end
    ...
end
```

- RISC-V 规定：低 2 位为 11 表示 32 位指令，否则为 16 位压缩指令；据此得到 **is16bit[]** / **is32bit[]**，再结合 **pc[]** 计算各指令的 PC 和跳转目标（CJ_target、CB_target、J_target、B_target 等），并匹配 c.j/c.jal/c.jr/c.jalr/c.beqz/c.bnez 以及 jal/jalr/branch，生成 **branch[]** 和最终的 **decBranch_c** / **endOffs**。

## 六、InstrAligner（IF_Instr → PD_Instr）

InstrAligner 的职责：把**一个 IF_Instr**（8 个半字 + firstValid/lastValid）按 **16/32 位边界**拆成多条指令，并输出 **NUM_INSTRS** 条 **PD_Instr**（本工程为 4 条），供解码器使用。

### 6.1 指令边界（当前包 + 上一包残留）

```38:64:src/InstrAligner.sv
always_comb begin
    ...
    validInstrStart_c = !(prev_r[BUF_SIZE-1].start[NUM_PACKETS-1] && prev_r[BUF_SIZE-1].start32[NUM_PACKETS-1]);

    for (integer i = 0; i < NUM_PACKETS; i=i+1) begin
        if (FetchOff_t'(i) < IN_op.firstValid || !IN_op.valid)
            validInstrStart_c = 0;
        if (FetchOff_t'(i) > IN_op.lastValid)
            validInstrStart_c = 0;

        if (validInstrStart_c) begin
            is32bit = (IN_op.instrs[i][1:0] == 2'b11);
            isInstrStart_c[i] = 1;
            isInstrStart32_c[i] = is32bit;
            validInstrStart_c = !is32bit;
        end
        else begin
            isInstrStart_c[i] = 0;
            isInstrStart32_c[i] = 0;
            validInstrStart_c = 1;
        end
    end
end
```

- **firstValid/lastValid** 限定本包有效半字范围；**prev_r** 记录上一周期是否在包尾有未消费的 32 位指令后半部分。
- 每个半字位置 i：若在有效范围内且 **validInstrStart_c**，则根据 **instrs[i][1:0]** 标 **is32bit** / **isInstrStart_c**，并决定下一位置是否仍是指令起点。

后续逻辑根据 **isInstrStart_c** / **isInstrStart32_c** 和 **IN_op.instrs** 拼出每条指令的 32 位编码与 PC，填入 **OUT_instr[]**（PD_Instr），并带上 fetchID、fetchFault、predTarget、predTaken 等，此处不逐行展开。

## 七、I-Cache / ICTable 在 SoC 中的连接（SoC.sv）

取指读出的 **IF_icache** / **IF_ict** 在 SoC 中接到实际存储与内存请求：

- **IF_ict**：连接到与 I-Cache 同索引的 **Tag 存储**（MemRTL1RW 等），用于 VIPT 的 tag 比较（物理 tag）。
- **IF_icache**：连接 I-Cache 的 **数据存储**；若 cache 未命中，通过 **OUT_memc** 向 MemoryController 发起 **MEMC_CP_EXT_TO_CACHE**，填满一行后更新 ICTable 和 I-Cache 数据，下次同一索引+匹配 tag 即可 hit。

具体端口与位宽见 **SoC.sv** 中 `IF_icache` / `IF_ict` 与 CacheLineManager、MemRTL 等的连线。

## 八、小结：取指路径一览

| 阶段 | 位置 | 内容 |
|------|------|------|
| 1. 下一 PC | BranchPredictor | pcReg → OUT_pc；BTB/TAGE/ReturnStack 决定是否跳转及目标 |
| 2. 发请求 | IFetch | ifetchOp.valid=1, ifetchOp.pc={pc,1'b0}（当 !stall && !mispred） |
| 3. 第 0 拍 | IFetchPipeline | fetch0 ← ifetchOp；IF_icache.re/IF_ict.re，raddr=pc[VIRT_IDX_LEN-1:0] |
| 4. 第 1 拍 | IFetchPipeline | fetch1 ← fetch0，分配 fetchID；TLB 用 fetch0.pc → phyPC；ICTable 与 phyPC 比较 → assocHit；IF_icache.rdata[assocHit.idx] → packet.instrs |
| 5. 组包 | IFetchPipeline | 故障则只填 fetchFault；hit 则填 packet.instrs + pred 等 → packet |
| 6. 修正预测 | BranchHandler | 扫描 packet.instrs，修正 lastValid/pred → packetRePred |
| 7. 输出 | outFIFO → InstrAligner | packetRePred 入 FIFO；InstrAligner 按 16/32 位边界拆成 PD_Instr[] → 解码器 |

配合本文档中的代码引用，可以按「PC 来源 → ifetchOp → fetch0/fetch1 → TLB/cache → packet → packetRePred → FIFO → InstrAligner → PD_Instr」的顺序在工程中逐行对照阅读。
