# SoomRV 分支预测实现详解

本文档结合代码逐级说明分支预测的**预测路径**（取指时如何给出下一 PC 与方向）、**更新路径**（执行/提交后如何更新 BTB、TAGE、ReturnStack），以及**错误预测恢复**（mispred 时如何恢复 PC 与历史）。

---

## 一、整体结构概览

### 1.1 分支预测在流水线中的位置

```
                    ┌─────────────────────────────────────────────────────────┐
                    │                  BranchPredictor                         │
                    │  ┌──────────┐  ┌──────────────┐  ┌──────────────┐        │
                    │  │ BTB      │  │ TagePredictor │  │ ReturnStack  │        │
                    │  │ (目标)   │  │ (方向)       │  │ (返回地址)   │        │
                    │  └────┬─────┘  └──────┬───────┘  └──────┬───────┘        │
                    │       │               │                 │                 │
                    │       └───────────────┼─────────────────┘                 │
                    │                       ▼                                   │
                    │              OUT_pc, OUT_predBr, OUT_lastOffs            │
                    │              OUT_curRetAddr, OUT_lateRetAddr, OUT_rIdx     │
                    └────────────────────────┬────────────────────────────────┘
                                             │
         ┌───────────────────────────────────┼───────────────────────────────────┐
         │ IFetch                              │                                    │
         │   ifetchOp.pc = {OUT_pc, 1'b0}      │   IN_btUpdates[] (BranchHandler,   │
         │   BP_mispr ← IN_branch / BH_fetch   │    IntALU 等) → BTB 更新            │
         │   Branch / IN_decBranch             │   IN_bpUpdate (ROB 提交) → TAGE   │
         └───────────────────────────────────┴───────────────────────────────────┘
```

- **预测**：每个取指使能拍，BranchPredictor 根据当前 **pcReg** 查 BTB、TAGE、ReturnStack，输出 **OUT_pc**（下一拍取指地址）和 **OUT_predBr**（本包预测分支信息）；IFetch 用 OUT_pc 生成 ifetchOp.pc。
- **更新**：
  - **BTB**：由 **IN_btUpdates[]** 更新（来自 BranchHandler 的“取指时发现的新分支”和 IntALU 的“执行时确认的间接跳转目标”）。
  - **TAGE 方向**：由 **IN_bpUpdate** 更新（ROB 在分支指令**提交**时送出，包含 fetchID、fetchOffs、branchTaken）。
- **恢复**：**IN_mispr**（FetchBranchProv）表示本拍发生错误预测或前端修正；BranchPredictor 用 IN_mispr 恢复 **pcReg**、**history**、**ReturnStack**，并可选地读 **PCFile/BPFile** 得到恢复用的 PC 与历史。

## 二、BranchPredictor 顶层（src/BranchPredictor.sv）

### 2.1 接口与子模块

- **OUT_pc**：当前拍输出的“下一取指地址”（半字地址 30 位）。
- **OUT_predBr**：本拍预测分支（目标、偏移、类型、taken、dirOnly）。
- **OUT_lastOffs**：上一拍 PC 对应包内“最后一个有效半字”的偏移。
- **OUT_curRetAddr / OUT_lateRetAddr**：ReturnStack 给出的当前/延迟返回地址。
- **OUT_stall**：与 ReturnStack 恢复中产生的 stall 一致（**RET_stall**）。
- **IN_mispr**：错误预测或前端修正；**IN_bpUpdate**：提交时的方向更新；**IN_btUpdates[]**：BTB 更新；**IN_retDecUpd**：取指阶段发现的 call 的返回地址（用于 ReturnStack push）。

子模块：
- **BranchTargetBuffer (btb)**：按 **OUT_pc** 查表，输出 **BTB_br**（PredBranch）。
- **TagePredictor (tagePredictor)**：按 **OUT_pc** 与 **lookupHistory** 查表，输出 **TAGE_taken**、**TAGE_tageID**、**TAGE_altPred**。
- **ReturnStack (retStack)**：输出 **OUT_curRetAddr**、**OUT_predBr**（RET_br，仅当预测为 return 时使用）。

### 2.2 本拍预测逻辑（OUT_pc、OUT_predBr）——组合逻辑

```96:139:src/BranchPredictor.sv
always_comb begin
    OUT_predBr = '0;
    OUT_predBr.dst = OUT_curRetAddr;
    OUT_predBr.offs = {$bits(FetchOff_t){1'b1}};

    OUT_pc = pcReg;
    OUT_lastOffs = {$bits(FetchOff_t){1'b1}};

    if (ignorePred) begin
        if (recovery.valid && recovery.tgtSpec != BR_TGT_MANUAL)
            OUT_pc = recoveredPC;
    end
    else if (BTB_br.valid && BTB_br.btype != BT_RETURN) begin
        OUT_predBr = BTB_br;
        OUT_predBr.taken |= TAGE_taken;
        OUT_predBr.multiple = !OUT_predBr.taken && BTB_br.multiple;

        if (OUT_predBr.taken) begin
            OUT_pc = OUT_predBr.dst;
            OUT_lastOffs = OUT_predBr.offs;
        end
        if (OUT_predBr.multiple && OUT_predBr.offs != {$bits(FetchOff_t){1'b1}}) begin
            OUT_lastOffs = OUT_predBr.offs;
            OUT_pc = {pcRegNoInc[30:$bits(FetchOff_t)], OUT_predBr.offs + 1'b1};
        end
    end
    else if (BTB_br.valid && BTB_br.btype == BT_RETURN && RET_br.valid) begin
        OUT_predBr = BTB_br;
        OUT_predBr.taken = 1;
        OUT_predBr.dst = OUT_curRetAddr;
        OUT_pc = OUT_predBr.dst;
        OUT_lastOffs = OUT_predBr.offs;
    end
    else begin
        OUT_predBr.valid = 1;
        OUT_predBr.btype = BT_BRANCH;
        OUT_predBr.dirOnly = 1;
        OUT_predBr.taken = TAGE_taken;
    end
end
```

- **ignorePred**：上一拍发生了 mispred，本拍处于“恢复”状态，**OUT_pc** 用 **recoveredPC**（见下），不再用 BTB/TAGE/ReturnStack 的结果。
- **BTB 命中且非 return**：  
  - 用 BTB 的目标与偏移填 **OUT_predBr**；**taken** 在 JUMP/CALL 时 BTB 已为 1，在 BRANCH 时再与 **TAGE_taken** 或。  
  - 若 **taken**：**OUT_pc = OUT_predBr.dst**，**OUT_lastOffs = OUT_predBr.offs**。  
  - 若 **multiple** 且 offs 有效：表示同包内有多分支、预测不跳，下一取指从 **offs+1** 半字继续，**OUT_pc** 为对应半字地址。
- **BTB 命中且为 return 且 RET_br.valid**：**OUT_pc = OUT_curRetAddr**（ReturnStack 栈顶）。
- **否则**：仅做**方向预测**，**OUT_predBr.dirOnly=1**，**OUT_predBr.taken = TAGE_taken**；**OUT_pc** 仍为 **pcReg**（顺序下一包由下面 pcReg 更新体现）。

### 2.3 pcReg 与 recovery（时序）

```326:368:src/BranchPredictor.sv
reg[30:0] pcReg;
reg[30:0] pcRegNoInc;
reg ignorePred;
always_ff@(posedge clk ...) begin
    recovery <= Recovery'{valid: 0, default: 'x};

    if (rst) begin
        pcReg <= 31'(`ENTRY_POINT >> 1);
        ignorePred <= 1;
        history <= 0;
    end
    else begin
        if (IN_pcValid) begin
            pcReg <= {OUT_pc[30:$bits(FetchOff_t)] + 1'b1, $bits(FetchOff_t)'(1'b0)};
            pcRegNoInc <= OUT_pc;
            ignorePred <= 0;
            history <= lookupHistory;
        end
        else if (recovery.valid) begin
            history <= recHistory;
            if (recovery.tgtSpec != BR_TGT_MANUAL)
                pcReg <= recoveredPC;
        end

        if (IN_mispr.taken) begin
            recovery.valid <= 1;
            recovery.tgtSpec <= IN_mispr.tgtSpec;
            recovery.fetchID <= IN_mispr.fetchID;
            recovery.retAct <= IN_mispr.retAct;
            recovery.histAct <= IN_mispr.histAct;
            recovery.fetchOffs <= IN_mispr.fetchOffs;

            pcReg <= IN_mispr.tgtSpec == BR_TGT_MANUAL ? IN_mispr.dst : 'x;
            ignorePred <= 1;
        end
    end
end
```

- **IN_pcValid** 为 1（取指使能）：  
  - **pcReg** 更新为「本拍 **OUT_pc** 按 16 字节对齐后的下一包」：高 30-FetchOff 位 +1，低 FetchOff 位清 0。  
  - **pcRegNoInc** 保存本拍 **OUT_pc**，供 BTB/多分支逻辑使用。  
  - **history** 用 **lookupHistory**（见下）。
- **IN_mispr.taken**：  
  - 置 **recovery**，下一拍起 **ignorePred=1**，**pcReg** 若为 **BR_TGT_MANUAL** 则已被设为 **IN_mispr.dst**；否则在 **else if (recovery.valid)** 中用 **recoveredPC** 更新 **pcReg**。
- **recoveredPC** 的计算（组合逻辑）：

```83:92:src/BranchPredictor.sv
logic[30:0] recoveredPC;
always_comb begin
    recoveredPC = {IN_pcFileRData.pc[30:$bits(FetchOff_t)], recovery.fetchOffs};
    case (recovery.tgtSpec)
        BR_TGT_CUR32: recoveredPC = recoveredPC - 1;

```

即：从 **PCFile** 读出的恢复用 PC 高段 + **recovery.fetchOffs**，再按 **tgtSpec** 做 ±1 或不变。

### 2.5 预测时的历史与更新时的历史

**lookupHistory**（预测时送入 TAGE 和 ReturnStack 恢复）：  
- 若 **recovery.valid**：用 **recHistory**（从 BPFile 读出并按 recovery 的 histAct/同包内 pred 修正）。  
- 否则若本拍预测为“有效条件分支”（非 dirOnly）：在 **history** 末尾追加本拍 **OUT_predBr.taken**。  
- 否则为 **history**。

**recHistory**：  
- 以 **bpFileRData.history** 为基，若同包内更早有一条预测分支且 recovery.fetchOffs 在其后，则先恢复该预测位；再按 **recovery.histAct** 做 APPEND/WRITE。

**updHistory**（TAGE 写入时）：  
- 以 **bpFileRData.history** 为基，若存在同包内更早的条件分支且 **bpUpdateActive.fetchOffs** 在其后，则追加该分支的预测结果。

（代码见 BranchPredictor.sv 的 recHistory、lookupHistory、updHistory 的 always_comb。）

### 2.6 BP 备份（bpFile）与 OUT_fetchLimit

每个取指包在**取指拍**会把当前预测状态写入 **BPFile**（地址 **IN_fetchID**），内容为 **bpBackup**（history、rIdx、predTaken、predOffs、tageID、altPred 等）。错误预测或方向更新时，用 **fetchID** 读回该备份，用于恢复或 TAGE 更新。

**OUT_fetchLimit**：当有 **bpUpdate** 或 **IN_bpUpdate.valid** 时，限制前端不要分配超过该 **fetchID** 的新包，避免覆盖尚未用于更新的 PC/BP 条目。

## 三、BranchTargetBuffer（BTB）（src/BranchTargetBuffer.sv）

### 3.1 作用与表项

BTB 用**取指 PC**（半字地址 **IN_pc**）索引，存“该 PC 所在 cache 行内曾出现过的分支”的**目标地址**、**类型**、**包内偏移**等，供预测时直接给出跳转目标。

```15:24:src/BranchTargetBuffer.sv
typedef struct packed
{
    BranchType btype;
    logic compr;
    logic valid;
    logic[30:0] dst;
    logic[`BTB_TAG_SIZE-1:0] src;
    FetchOff_t offs;
} BTBEntry;
```

- **src**：tag，与索引一起唯一标识一条预测（高位 PC + 包内位置）。
- **dst**：目标半字地址。
- **offs**：该分支在 16 字节包内的半字偏移。

### 3.2 读路径（预测）

```41:67:src/BranchTargetBuffer.sv
always_ff@(posedge clk) begin
    if (IN_pcValid) begin
        fetched.entry <= entries[IN_pc[$clog2(LENGTH)-1:0]];
        fetched.multiple <= multiple[IN_pc[$clog2(LENGTH)-1:0]];
        fetched.pc <= IN_pc;
    end
end
always_comb begin
    OUT_branch = PredBranch'{valid: 0, default: 'x};

    if (fetched.entry.valid &&
        fetched.entry.src == fetched.pc[$clog2(LENGTH)+:`BTB_TAG_SIZE] &&
        fetched.entry.offs >= fetched.pc[0+:$bits(FetchOff_t)]
    ) begin
        OUT_branch.valid = 1;
        OUT_branch.multiple = fetched.multiple;
        OUT_branch.dst = fetched.entry.dst;
        OUT_branch.btype = fetched.entry.btype;
        OUT_branch.compr = fetched.entry.compr;
        OUT_branch.offs = fetched.entry.offs;
        OUT_branch.taken = fetched.entry.btype == BT_CALL || fetched.entry.btype == BT_JUMP;
        OUT_branch.dirOnly = 0;
    end
end
```

- 索引：**IN_pc** 的低 **log2(BTB_ENTRIES)** 位。  
- Tag 比较：**fetched.entry.src** 与 **fetched.pc** 的 tag 段相等，且 **entry.offs >= pc** 在包内的半字偏移（保证预测的是“当前或之后”的分支）。  
- 命中则输出 **dst/btype/offs**；**taken** 对 CALL/JUMP 直接为 1，对 BRANCH 由 BranchPredictor 与 TAGE_taken 或。

### 3.3 写路径（更新）

- **IN_btUpdate.clean=1**：清除该索引对应项（**valid=0**）。  
- **IN_btUpdate.clean=0**：写入新目标。索引由 **src** 的高位 + **fetchStartOffs** 组成；若 **multiple**，还会对前一条分支所在项设 **multiple[]=1**，表示“同包内还有后一条分支，预测不跳时 lastValid 截断到前一条”。  
- 具体索引与 multiple 的维护见 BranchTargetBuffer.sv 的 always_ff 写块（约 77–128 行）。

## 四、TagePredictor（方向预测）（src/TagePredictor.sv）

### 4.1 结构

- **1 个 base 预测器**：BranchPredictionTable，索引为 PC 的低 **BP_BASEP_ID_LEN(12)** 位，输出 **predictions[0]**（bimodal 方向）。  
- **NUM_STAGES-1 个 TAGE 表**：每个表用 (PC, history) 的 hash 做索引，用 (PC, history) 的 tag 做匹配；匹配则输出该表的 **predictions[i]**，且 **valid[i]=1**。  
- 最终输出：**OUT_predTaken** = 命中表中**编号最大**的那一表的预测；**OUT_altPred** = 比该表小一号的命中表预测（若无则用 base）；**OUT_predTageID** = 命中表编号。用于分配新项、useful 更新等。

### 4.2 Hash 与 Tag（与 history 折叠）

```56:79:src/TagePredictor.sv
always_comb begin
    for (integer i = 0; i < NUM_STAGES-1; i=i+1) begin
        integer hist_bits = (BASE * (FACTOR ** i));

        predTags[i] = IN_predAddr[TAG_SIZE-1:0];
        writeTags[i] = IN_writeAddr[TAG_SIZE-1:0];

        predHashes[i] = 0;
        writeHashes[i] = 0;

        for (integer j = 0; j < ($bits(IN_predAddr)/HASH_SIZE); j=j+1) begin
            predHashes[i] = predHashes[i] ^ IN_predAddr[j*HASH_SIZE+:HASH_SIZE];
            ...
        end
        for (integer j = 0; j < (BASE * (FACTOR ** i)); j=j+1) begin
            predHashes[i][j % HASH_SIZE] ^= IN_predHistory[j];
            ...
            predTags[i][j % TAG_SIZE] ^= IN_predHistory[j] ^ IN_predHistory[(j+1) % hist_bits];
            ...
        end
    end
end
```

- 第 i 个 TAGE 表使用 **BASE * FACTOR^i** 位历史，与 PC 一起折叠成 **predHashes[i]**、**predTags[i]**，实现 TAGE 的“不同历史长度”表。

### 4.4 更新（提交后）

- **IN_writeValid**：来自 **bpUpdateActive.valid**（ROB 提交的分支方向更新）。  
- **IN_writeAddr**：**IN_pcFileRData.pc**（该分支取指时的 PC，与预测时一致）。  
- **IN_writeTaken**：实际方向 **bpUpdateActive.branchTaken**；**IN_writePred**：当时预测方向 **bpFileRData.predTaken**；**IN_writeAltPred**：**bpFileRData.altPred**。  
- **IN_writeTageID**：**bpFileRData.tageID**（命中表编号）。  
- 若 **IN_writeTaken != IN_writePred**（方向错误）：可能 **doAlloc** 在更高 stage 分配新项（带一定随机率）；若 **IN_writeTageID** 对应表项存在且 **IN_writeUseful**（预测与 altPred 不同），则根据 **IN_writeCorrect** 增减 **useful** 计数。  
- TageTable 内部：**IN_writeUpdate** 时更新计数器或 useful；**IN_doAlloc** 且该表项 useful==0 时分配新 tag 与预测；**IN_allocFailed** 时可能减少 useful。

## 五、ReturnStack（src/ReturnStack.sv）

### 5.1 作用

- 在**预测到 call** 时 **push** 返回地址（call 下一条指令）；在**预测到 return** 时 **pop** 出栈顶作为预测目标。  
- 使用 **rindex** 指向当前栈顶；**IN_branch** 为 CALL 时 rindex+1 并 push **addrToPush**；为 RETURN 时 rindex-1，**OUT_curRetAddr** = **rstack[rindex]**。

### 5.2 Push 与栈顶输出

```56:72:src/ReturnStack.sv

...

    if (forwardRindex) begin
        rindex = IN_recoveryIdx;

    else if (IN_branch.valid && IN_branch.btype == BT_CALL && lastValid) begin

```


- **addrToPush**：当前包 PC 高段 + 预测分支偏移 +1，即 call 下一条指令（半字）地址。  
- **forwardRindex**：mispred 后从 **IN_recoveryIdx**（由 BPFile 读出的 rIdx 经 retAct 修正）恢复栈指针。

### 5.3 恢复队列（rrqueue）

- 每次 **push**（预测 call）时，把**被覆盖的旧栈内容**和 (fetchID, offs, idx) 记入 **rrqueue**。  
- **mispred** 后进入 **recoveryInProgress**，按 **recoveryID/recoveryOffs** 与队列中条目比较，把尚未提交的 push 从队列“还原”回 **rstack**，恢复栈状态。  
- **IN_comFetchID** 推进时，已提交的队列条目从队尾丢弃（**lastInvalComFetchID** 与 qindexEnd 逻辑）。

## 六、BranchHandler（取指阶段目标/方向修正）（src/BranchHandler.sv）

BranchHandler 在**取指包刚从 I-Cache 返回**后，根据**实际指令**扫描本包内所有分支，与**预测**（IN_op.predBr）对比，若不一致则产生 **OUT_decBranch**（FetchBranchProv）、**OUT_btUpdate**、**OUT_retUpdate**，并可能截断 **lastValid**（endOffs）。

### 6.1 预测了跳转但实际不对

- 预测了跳转（**predicted && IN_op.predBr.taken**），但：包内该位置**没有分支**、或**类型/目标不符**、或**目标错误**：  
  - 置 **decBranch_c.taken=1**，**dst** 为正确目标或 nextPC；**retAct/histAct** 按实际分支类型设置；若需删除错误 BTB 项则 **btUpdate_c.clean=1**；若目标可修正则 **btUpdate_c.clean=0** 并写正确 **dst/btype**。  
  - 若预测落在 32 位指令前半（**predIllegal**），则 **decBranch_c.dst = curPC**，并设 **endOffsValid/endOffs** 截断包。  
- 代码见 BranchHandler.sv 约 287–374 行。

### 6.2 未预测跳转但实际有跳转

- **curBr.valid** 且（JUMP/CALL/RETURN 或 dirOnly 且预测 taken）：  
  - **decBranch_c.taken=1**，**dst** 为实际目标或 **predRetAddr**（return）；**retAct** 为 RET_PUSH/RET_POP；**newPredTaken_c/newPredPos_c** 更新包内预测信息。  
  - 同时 **btUpdate_c.valid=1**，**clean=0**，写入该分支的 **src/dst/btype**，供 BTB 学习。  
- 若为**未预测的条件分支不跳**或 **ICALL**：仍 **decBranch_c.taken=1**，**dst=nextPC**，**histAct=APPEND_0** 或 NONE，并可能写 BTB（不跳时的目标或占位）。  
- 见 376–441 行。

### 6.3 预测了不跳但该位置没有分支

- **decBranch_c.taken=1**，**dst=nextPC**，**btUpdate_c.clean=1** 删除错误 BTB 项，**endOffsValid** 截断到该偏移。  
- 见 452–436 行。

BranchPredictor 侧：**IN_btUpdates[]** 中包含 BranchHandler 送出的 **OUT_btUpdate**（与 IntALU 的 BTUpdate 一起在 BranchPredictor 内合并为 **btUpdate** 写入 BTB）。

## 八、数据流小结

| 阶段 | 内容 |
|------|------|
| **预测** | pcReg → BTB(TAG+索引) → BTB_br；pcReg + lookupHistory → TAGE → TAGE_taken；ReturnStack 给出 OUT_curRetAddr。组合逻辑合并为 OUT_pc、OUT_predBr。下一拍 pcReg 更新为顺序下一包或跳转目标。 |
| **BTB 更新** | BranchHandler（取指时新分支/目标错误）→ OUT_btUpdate；IntALU（间接跳转目标）→ OUT_btUpdate。BranchPredictor 合并 IN_btUpdates 后写 BTB。 |
| **TAGE 更新** | ROB 提交分支 → OUT_bpUpdate；BranchPredictor 的 updFIFO → bpUpdateActive；读 BPFile 得 tageID/altPred/history → 写 TagePredictor。 |
| **ReturnStack** | 预测 CALL 时 push(addrToPush)，预测 RETURN 时 OUT_curRetAddr=rstack[rindex]；BranchHandler/IntALU 的 retAct 在 mispred 时用于恢复；IN_retDecUpd 为取指阶段发现的 call 返回地址。 |
| **错误预测恢复** | BranchSelector 选最早 taken 的 BranchProv → IN_branch；IFetch 将 IN_branch/BH_fetchBranch/IN_decBranch 转为 BP_mispr；BranchPredictor 置 recovery、ignorePred，pcReg 设为 dst 或 recoveredPC，history/ReturnStack 用 BPFile/PCFile 与 recRIdx 恢复。 |

结合上述模块与引用行号，可在工程中按“预测 → 更新 → 恢复”三条线逐行对照阅读分支预测实现。
