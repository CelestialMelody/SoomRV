恭喜您，阅读完 `Config.sv` 和 `Include.sv`，您已经完成了最枯燥但最基础的“扫盲”工作。

作为项目学习者，您从这两个文件中应该提取出以下**三个核心认知**，这将指导您后续的代码阅读：

### 1. 您心中应该建立的 SoomRV 画像

* **它是一个“偏科”的学霸：**
* **前端很强：** 4路取指 + TAGE 预测器（这是现代高性能 CPU 的标配）。
* **后端很挤：** 只有 64 个物理寄存器（`RF_SIZE_EXP 6`）和 64 项 ROB。这意味着如果不修改配置，它的乱序窗口很小，一旦遇到 Cache Miss，流水线很容易塞满停顿。


* **独特的 "Load-after-Issue" 架构：**
* 您在 `IS_UOp`（发射队列微操作）中没看到 32位操作数，只看到了 `Tag`。
* 这意味着：**指令在发射队列里排队时，只带着“号牌”（Tag），不带“数据”。** 只有当它被发射出去后，才去物理寄存器堆（PRF）拿数据。这大大减小了发射队列的面积，但增加了一个流水级。


* **一切皆微操作 (UOp)：**
* RISC-V 指令进入解码器后，就变成了 `UOp`。后续所有模块（ROB, ALU, LSU）只认 `UOp` 结构体，不再关心原始指令编码。



### 2. 您掌握的“通关密语”

在后续阅读中，您会反复看到以下字段，请务必形成条件反射：

* **`sqN` (序列号)：** 看到它，就要想到 **“顺序”**。这是 ROB 用来在乱序执行中维持程序逻辑顺序的唯一凭证。
* **`Tag` (标签)：** 看到它，就要想到 **“依赖”**。这是指令间传递数据的纽带（A 算完了告诉 B，B 就可以走了）。
* **`valid` / `avail`：** 看到它，就要想到 **“握手”**。这是流水线流动的红绿灯。

### 3. 下一步读什么？（阅读路线）

既然我们已经懂了“语言”（Structs）和“规模”（Config），下一步就该看它们是怎么**组装**在一起的。

**推荐阅读顺序：**

#### **第一步：上帝视角 (Top Level)**

* **目标文件：** **`src/Core.sv`**
* **为什么：** 它是 CPU 的主板。您需要看清楚 `IFetch` 模块吐出的 `IF_Instr` 包是怎么传给 `Rename` 的，`Rename` 又是怎么把 `R_UOp` 塞进 `IssueQueue` 的。
* **看点：** 关注模块之间的**连线接口**，不要陷入具体的 `always` 逻辑块。

#### **第二步：数据的源头 (Frontend)**

* **目标文件：** `src/IFetch.sv` 和 `src/InstrDecoder.sv`
* **为什么：** 看看指令是如何诞生的，以及如何被翻译成我们刚刚熟悉的 `D_UOp`。

#### **第三步：乱序的大脑 (The OoO Engine)**

* **目标文件：** `src/Rename.sv` 和 `src/ROB.sv`
* **为什么：** 这是最难也是最精彩的部分，理解 `Tag` 是如何分配和回收的。
