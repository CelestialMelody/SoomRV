`src/Config.sv` 是 SoomRV 处理器的**全局配置文件**。它定义了处理器的核心参数，如缓存大小、流水线宽度、队列深度以及功能单元的分配。

理解这个文件对于掌握处理器的**规模**（它是大核还是小核）和**能力**（它能并行做什么）至关重要。

以下是按功能模块划分的详细解读：

### 1. 前端与预测 (Frontend & Prediction)

这部分定义了处理器“抓取指令”的能力和“猜测跳转”的精度。

* **分支预测 (Branch Prediction):**
* 
`BTB_ENTRIES 4096`: **分支目标缓冲 (BTB)** 有 4096 个条目 。这是一个相当大的容量，意味着它能记住大量跳转指令的目标地址，减少取指气泡。


* 
`TAGE_*`: 配置了 **TAGE 预测器**（一种高性能的分支方向预测算法）。它包含 256 个条目的基础表 和 6 个阶段的历史表 ，用于处理复杂的条件跳转模式。


* 
`RETURN_SIZE 32`: **返回栈 (RAS)** 深度为 32 ，用于预测函数返回地址。




* **取指与解码 (Fetch & Decode):**
* 
`FETCH_BITS`: 取指带宽。`16 << (4-1)` = 128 bit (16 字节) 。每个周期能从 Cache 拉取 16 字节指令。


* 
`DEC_WIDTH 4`: **解码宽度 4** 。这是其“4-wide 超标量”身份的直接证据，每个周期最多解码 4 条指令。


* 
`PD_BUF_SIZE 4`: 预解码缓冲大小 。





### 2. 核心资源 (Core Resources)

这部分决定了处理器的乱序执行窗口大小（即它能“看多远”）。

* **ROB (Re-Order Buffer):**
* 
`ROB_SIZE_EXP 6`:  个条目 。


* **解读：** 这是一个中等偏小的窗口。现代高性能核通常在 100+。这意味着一旦有长延迟指令（如 Cache Miss）阻塞队头，整个流水线最多只能再容纳 63 条指令就会停顿。


* **寄存器堆 (Register File):**
* 
`RF_SIZE_EXP 6`:  个物理寄存器 。


* **解读：** **非常紧张！** RISC-V 架构寄存器有 32 个（x0-x31），剩下只有  个物理寄存器可用于重命名（Renaming）。这进一步限制了实际的乱序并发能力。



### 3. 内存子系统 (Memory Subsystem)

定义了缓存和内存队列的规模。

* **队列 (Queues):**
* 
`SQ_SIZE 16`: **存储队列**深度 16 。


* 
`LB_SIZE 16`: **加载队列**深度 16 。




* **TLB (页表缓冲):**
* 
`ITLB_SIZE 8`, `DTLB_SIZE 8`: 指令和数据 TLB 只有 8 个条目 ，这非常小。但它是全相联的（Implied by logic usually, though typical for small TLBs），用于加速虚实地址转换。




* **Cache:**
* 
`CASSOC 4`: 4路组相联 。


* 
`VIRT_IDX_LEN 12`: 虚拟索引长度 12位 。这通常对应 Page Size (4KB)，是 VIPT Cache 的典型配置。




* **总线 (Bus):**
* 
`AXI_WIDTH 128`: AXI 总线宽度 128位 ，与 Cache Line 大小和取指宽度匹配，保证高吞吐。





### 4. 执行引擎配置 (Execution Engine) - **核心重点**

这部分定义了有多少个运算单元，以及它们如何分配到发射端口。

* **单元数量:**
* 
`NUM_AGUS 2`: 2 个地址生成单元（负责算内存地址） 。


* 
`NUM_ALUS 3`: 3 个算术逻辑单元（负责加减乘除等） 。


* 
**总端口数:** `NUM_PORTS = 5` (2 AGU + 3 ALU) 。




* **发射队列 (Issue Queues):**
* 
`PORT_IQ_SIZE`: 每个端口都有独立的 **8 条目** 发射队列 。这意味着总共有  个待发射指令槽位。




* **端口功能映射 (`PORT_FUS`):**
这是最关键的配置，决定了哪种指令去哪里执行 ：


| 端口 (Index) | 类型 | 支持的功能 (Bitmask) | 解读        |
| ------------ | ---- | -------------------- | ----------- |
| **0**        | AGU  | `FU_AGU`             | `FU_ATOMIC` |
| **1**        | AGU  | `FU_AGU`             | `FU_ATOMIC` |
| **2**        | ALU  | `INT`                | `MUL`       |
| **3**        | ALU  | `INT`                | `BRANCH`    |
| **4**        | ALU  | `INT`                | `BRANCH`    |


**分析：**
* 
**分支能力:** 只有端口 3 和 4 支持分支 (`NUM_BRANCH_PORTS = 2`) 。


* **乘除法:** 乘法有 2 个单元 (Port 2, 3)，除法只有 1 个 (Port 4)。
* **负载均衡:** 所有 ALU 端口都能处理最基础的 `INT` (加减法)，这有助于平衡负载。



### 5. 地址空间 (Address Map)

定义了物理内存布局，用于区分内存访问和 I/O 访问。

* 
`ENTRY_POINT 32'h8000_0000`: 复位后从 `0x80000000` 开始执行 。


* 
`IS_MMIO_PMA`: 地址小于 `0x80000000` 被认为是 MMIO (外设 I/O) 。


* 
`IS_MEM_PMA`: 地址在 `0x80000000` 到 `0x90000000` 之间是主存 (DRAM) 。



### 总结

通过 `Config.sv`，我们可以看出 SoomRV 是一个**激进的前端**（宽取指、强预测）搭配**紧凑的乱序后端**（ROB 和 RF 较小）的设计。它的执行端口分配非常合理，确保了常见指令（整数运算、Load/Store）有充足的并行度，而昂贵的指令（除法）则被限制在特定端口。
